# Better Fullstack Project

This project was generated by Better Fullstack. Treat the generated structure as
the source of truth when adding stack features, fixing bugs, or extending apps.

**This project was built with:** typescript ecosystem · tanstack-router · hono backend (bun) · trpc API · drizzle/postgres · better-auth · tailwind. The authoritative record of these choices is `bts.jsonc`.

## Project Rules

- Use `bun` for package-manager commands.
- Do not start a dev server unless the user explicitly asks.
- Prefer package-local scripts over broad workspace commands.
- Keep generated stack choices in `bts.jsonc` in sync with scaffold changes.
- For new Better Fullstack options, prefer the local Better Fullstack CLI or MCP
  update flow instead of hand-authoring unrelated starter code.

## Add a route or resource

This project exposes a **trpc** API. Routers live in `packages/api/src/routers/`, wired together in `packages/api/src/routers/index.ts`.

- Fastest path - scaffold a CRUD resource with the generator:

  ```bash
  bunx create-better-fullstack gen resource <name>
  ```

  It writes `packages/api/src/routers/<name>.ts` (auto-registered in `routers/index.ts`) using `protectedProcedure` (auth-gated) for every handler.

- Manual path - create `packages/api/src/routers/<name>.ts` exporting a `<name>Router`, then import it in `routers/index.ts` and add `<name>: <name>Router` to `appRouter`.
- tRPC procedures chain `.input(z.object({ ... }))` then `.query(...)` (reads) or `.mutation(...)` (writes); `appRouter` is built with `router({ ... })`.

## Run migrations

Schema lives in `packages/db/src/schema/`. After editing it:

```bash
bun run db:generate   # drizzle-kit generate (create SQL migration)
bun run db:migrate    # drizzle-kit migrate (apply migrations)
```

For rapid local iteration you can push the schema directly with `bun run db:push` (drizzle-kit push).

## Add a test

Unit tests use **Vitest**. Add `*.test.ts` files next to the code under test and run:

```bash
bun run test
```

End-to-end tests use **Playwright** in `apps/web` - add specs under its `e2e`/`tests` directory and run the app's `test:e2e` script.
